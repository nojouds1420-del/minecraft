# لوحة تحكم سيرفر ماينكرافت (Live Dashboard)

موقع بلوحة تحكم حية تعرض: عدد اللاعبين المتصلين الآن، الألعاب المتاحة وعدد
اللاعبين في كل لعبة، توب كيلز، وتوب كل لعبة على حدة. الواجهة الخلفية بلغة
بايثون (Flask)، والواجهة الأمامية HTML/CSS/JS بسيطة بدون أي إطار عمل معقّد.

**حالياً المشروع مربوط بسيرفر Hypixel العام** (وهو أكبر سيرفر عام متاح ويملك
API رسمي وموثّق) لغرض اختبار الشكل والوظائف وعرضها على العميل، قبل أن يكون
سيرفر العميل الخاص جاهزاً.

---

## التشغيل السريع

```bash
python3 -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# افتح .env وضع فيه مفتاح Hypixel (الخطوة التالية)

python3 app.py
```

بعدها افتح المتصفح على `http://127.0.0.1:5000`.

## الحصول على مفتاح Hypixel API (مجاني)

1. اذهب إلى: https://developer.hypixel.net/dashboard/ وسجّل الدخول بحسابك.
2. اضغط **Create Development Key** ثم أنشئ تطبيقاً (Application) جديداً.
3. انسخ المفتاح وضعه في ملف `.env` أمام `HYPIXEL_API_KEY=`.

مفتاح "Development" يكفي تماماً لهذا العرض التجريبي. لو احتجتم لاحقاً تشغيل
هذه اللوحة بشكل دائم وعلى نطاق واسع، يمكن التقديم لمفتاح "Production" من نفس
اللوحة.

## كيف تعمل البيانات فعلياً (مهم لفهم الفرق بين العرض التجريبي والسيرفر الخاص)

بروتوكول ماينكرافت القياسي (اللي يستخدمه أي عميل ماينكرافت لما يشوف عدد
اللاعبين في قائمة السيرفرات) يعطيك فقط: **عدد اللاعبين المتصلين، الحد
الأقصى، اسم السيرفر (MOTD)، والنسخة**. هذا الجزء يعمل مع **أي** سيرفر جافا،
عام أو خاص، بدون أي إعداد إضافي — وهو ما يقوم به `services/mc_status.py`
عبر مكتبة `mcstatus`.

لكن التفاصيل الأدق المطلوبة في المشروع — **كم شخص داخل كل لعبة تحديداً،
ومين توب كيلز، وتوب كل لعبة** — **ليست جزءاً من بروتوكول ماينكرافت نفسه**.
هذه بيانات يجب أن يوفرها السيرفر ذاته:

| المصدر | يعمل مع | ماذا يعطي |
|---|---|---|
| `mc_status.py` (بروتوكول Server List Ping) | أي سيرفر جافا، بدون أي شيء مثبّت عليه | عدد اللاعبين الكلي، MOTD، النسخة، البينغ |
| `hypixel_client.py` (Hypixel API العام) | سيرفر Hypixel فقط (لأنه هو من يوفر هذا الـ API) | تفصيل اللاعبين لكل لعبة ووضع، وترتيب (Leaderboard) حي لكل لعبة |
| **عند سيرفر العميل الخاص** | يحتاج بلَجن (Plugin) على Paper/Spigot يسجّل الإحصائيات في قاعدة بيانات (MySQL مثلاً) | نفس تفصيل الألعاب والكيلز، لكن من بيانات السيرفر الحقيقية 100% |

بمعنى آخر: عندما يجهز سيرفر العميل الخاص، الحل هو تركيب بلَجن إحصائيات
(Stats Plugin) — إما جاهز أو مبني خصيصاً — يسجّل كل قتلة (kill) وكل لعبة
يشارك فيها اللاعب في قاعدة بيانات. بعدها تُستبدل الاستدعاءات داخل
`services/hypixel_client.py` باستعلامات على تلك القاعدة مباشرة. لاحظوا أن
دوال `services/leaderboard_service.py` (`games_overview`,
`top_kills_board`, `leaderboards_for_game`) مصمّمة لتبقى بنفس الشكل تماماً
سواء جاءت البيانات من Hypixel أو من قاعدة بيانات السيرفر الخاص — فملف
`app.py` والواجهة الأمامية لن يحتاجا أي تعديل عند الانتقال، فقط الطبقة
الداخلية لجلب البيانات.

أما `mc_status.py` فهو **جاهز فعلاً** للعمل على السيرفر الخاص فور جهوزه —
فقط غيّروا `MC_SERVER_ADDRESS` في `.env` لعنوان السيرفر الجديد.

## ألعاب الموقع

قائمة الألعاب المعروضة كبطاقات (Duels, SMP, Minigames, Genblock) مو مسحوبة
تلقائياً من Hypixel — لأن سيرفركم الخاص بيوفر ألعاب محددة فقط، مو كل كتالوج
Hypixel. القائمة مُعرّفة يدوياً في `services/site_games.py`، وكل لعبة فيها
`hypixel_key` اختياري:

- إذا فيه `hypixel_key` (مثل Duels → `DUELS`, SMP → `SMP`, Minigames →
  `ARCADE`): البطاقة تعرض عدد لاعبين حي فعلي من Hypixel، والضغط عليها يفتح
  ترتيبها الحقيقي.
- إذا مافيه (`hypixel_key: None`) — زي **Genblock** لأنها لعبة خاصة مو
  موجودة على Hypixel أصلاً: البطاقة تظهر بشارة "قريباً" بدل رقم، والضغط
  عليها يعرض رسالة توضيحية بدل خطأ. بمجرد ربط الموقع بسيرفركم الخاص، تحطون
  لها بيانات حقيقية بدل هذا الرابط الفارغ.

> ملاحظة: أيقونات البطاقات حالياً رسومات SVG بسيطة رسمتها بنفسي (سيف،
> منزل، نرد، مكعّب) وليست صور أو سكرين شوت حقيقية من السيرفر — ما توفرت لي
> صور فعلية، وتجنبت استخدام أي رسومات من ماينكرافت أو Hypixel لتفادي مشاكل
> حقوق الملكية. لو تبون صور حقيقية (سكرين شوت من كل لعبة مثلاً)، حطوها في
> `static/img/` واستبدلوا وسم `<div class="game-icon">` في `app.js` بوسم
> `<img>` يشاور عليها.

**لإضافة أو تعديل لعبة:** افتحوا `services/site_games.py` وعدّلوا القائمة —
الاسم، الأيقونة (`sword`, `house`, `dice`, `cube` — أو ضيفوا رسمة SVG جديدة
في `ICONS` داخل `static/js/app.js`)، و`hypixel_key` إذا فيه مطابقة حقيقية.
باقي الكود (الـ API والواجهة) ما يحتاج أي تعديل.

## بنية المشروع

```
app.py                          مسارات Flask (API + الصفحة الرئيسية)
services/
  hypixel_client.py             اتصال بـ Hypixel API (counts + leaderboards)
  mojang_client.py              تحويل UUID → اسم اللاعب
  mc_status.py                  فحص أي سيرفر مباشرةً (بروتوكول ping)
  site_games.py                 قائمة ألعاب الموقع الثابتة (Duels, SMP, ...)
  leaderboard_service.py        يجمّع البيانات بالشكل اللي تحتاجه الواجهة
  cache.py                      كاش بسيط بالذاكرة يحمي من تجاوز حدود الـ API
templates/index.html            صفحة اللوحة
static/css/style.css            التصميم (نمط نيون سماوي/أزرق)
static/js/app.js                جلب البيانات دورياً وعرضها + أيقونات البطاقات
```

## ملاحظة مهمة حول "توب كيلز" في هذا العرض التجريبي

الـ Hypixel API يعطي ترتيب اللاعبين (Rank 1, 2, 3...) لكل لعبة، لكنه **لا
يعطي رقم القتلات الفعلي لكل لاعب** — فقط ترتيبه. لذلك تظهر اللوحة الترتيب
والاسم بدون رقم بجانبه. عند الانتقال لسيرفر العميل الخاص، بما إن البيانات
ستأتي من قاعدة بياناتكم الخاصة، سيكون بالإمكان عرض الرقم الفعلي (مثلاً
"4,201 قتلة") بجانب كل اسم بدون أي قيود.

## التخزين المؤقت (Cache)

كل الاستدعاءات الخارجية (Hypixel وMojang) تمر عبر كاش بسيط بالذاكرة لمدة
15-60 ثانية حسب نوع البيانات، حتى لو فتح العميل عدة تبويبات أو صفحات، ما
يخلّيكم دايماً ضمن حدود الطلبات المسموحة (Rate Limit) لكل من الخدمتين.

## النشر (Deployment)

هذا خادم تطوير (`python app.py`) مناسب للعرض والاختبار فقط. للنشر الفعلي،
استخدموا خادم WSGI حقيقي مثل gunicorn خلف nginx:

```bash
pip install gunicorn
gunicorn -w 2 -b 0.0.0.0:8000 app:app
```
